# Setup de Comunidad en Discord

El servidor de Discord debe ayudar a coordinar colaboradores sin reemplazar a GitHub como fuente de verdad. Las decisiones, tareas, bugs, pull requests y releases viven en GitHub. Discord sirve para conversación, onboarding, grupos de lectura y coordinación ligera.

## Nombre del servidor

Recomendado:

```text
Spectral Submersion Lab
```

## Principios

- Humildad científica: sin afirmaciones de desciframiento definitivo sin evidencia externa.
- Reproducibilidad: cada resultado debe enlazar código, datos y configuración.
- Respeto por comunidades de dominio, especialmente Rapa Nui y otros contextos culturales vivos.
- Colaboración abierta: una persona nueva debe entender dónde partir en menos de cinco minutos.

## Roles

| Rol | Propósito |
|------|---------|
| `maintainer` | Dirección del repo, releases, moderación |
| `research` | Metodología, papers, niveles de claim |
| `data` | Datasets, procedencia, licencias, releases en Drive |
| `engineering` | Código, tests, CI, performance |
| `domain-review` | Lingüística, arqueología, contexto cultural |
| `replication` | Reproducción de runs y reporte de divergencias |
| `community` | Onboarding, notas, calendario |

## Checklist de lanzamiento

1. Crear el servidor y los canales.
2. Agregar el código de conducta.
3. Fijar el repo, la carpeta de datos y la guía de contribución.
4. Crear una primera lista de `good first issue` en GitHub.
5. Publicar un mensaje breve de bienvenida.
6. Agregar la invitación en `linkedin_post.md`, `README.md` y `COMMUNITY_CALL.md`.

## Notas de moderación

- Mover decisiones técnicas grandes a GitHub issues.
- Pedir fuentes cuando alguien haga claims históricos o lingüísticos.
- Cerrar ciclos: si una conversación de Discord genera trabajo, crear issue o PR.
- No permitir claims sensacionalistas, falta de respeto cultural ni intercambio de datos privados.
- No permitir subida de archivos privados/restringidos; documentar solo metadata hasta tener permiso.
